# Dự án cuối Chương 3: Dựng database của công ty Sao Mai

Bản nháp chờ duyệt. Chuỗi 5 bài tập dạng "dựng table". Mỗi bài bắt đầu từ database mà bài trước để lại. Bài 1 bắt đầu từ database trống. Người học làm sau bài 10 của chương.

Công ty Sao Mai là công ty nhỏ. Người nhờ mình dựng database là chị Hạnh, trưởng phòng hành chính, và anh Quân, trưởng phòng kỹ thuật.

Năm table và thứ tự dựng:

| Bài | Phần dựng | Table |
|---|---|---|
| 1 | Phòng ban | `departments` |
| 2 | Nhân viên, có sếp và có phòng | `employees` |
| 3 | Dự án và phân công | `projects`, `assignments` |
| 4 | Đơn xin nghỉ phép | `leave_requests` |
| 5 | Nạp dữ liệu đúng thứ tự | cả năm table |

Quy ước chung của máy chấm:

- Máy chấm đọc cấu trúc table người học vừa tạo, rồi chạy vài phép thử hành vi trên một bản sao. Máy chấm tự thêm row mẫu vào table cha khi cần thử table con.
- "Nhóm data type" so theo nhóm, không so từng chữ. Nhóm số nguyên gồm INT và NUMBER. Nhóm chữ gồm VARCHAR và VARCHAR2. Nhóm số thập phân gồm DECIMAL và NUMBER(p,s). Nhóm ngày là DATE.
- Độ dài chữ phải đủ lớn: máy chấm chấp nhận mọi độ dài từ yêu cầu của đề trở lên.
- Lỗi khi viết sai cú pháp do engine báo. Bi dịch lỗi đó cho người học.
- Ghi chú cho người dựng engine: engine hiện chưa chạy được hai thứ bài này cần. Một là foreign key trỏ về chính table đang tạo (`manager_id` trỏ `employees`). Hai là DEFAULT: engine nhận cú pháp nhưng chưa tự điền giá trị khi INSERT thiếu column. Cả hai cần thêm vào engine trước khi dựng dự án (engine sẽ thêm).

## Bài 1: Table phòng ban

**Đề bài (Bi nói)**

"Chị Hạnh, trưởng phòng hành chính của Sao Mai, nhờ mình một chuyện. Chị cần một table giữ danh sách phòng ban. Mỗi phòng có một mã riêng, tự tăng. Tên phòng thì bắt buộc có và không được trùng. Nơi đặt phòng thì có phòng chưa biết, nên cho để trống. Bạn dựng table này giúp chị nhé."

**Yêu cầu**

- [ ] Table tên `departments`
- [ ] `department_id`: số nguyên, primary key, tự tăng
- [ ] `name`: chữ tối đa 50 ký tự, bắt buộc có, không trùng nhau
- [ ] `location`: chữ tối đa 50 ký tự, được để trống

**Lời giải mẫu**

MySQL:

```sql
CREATE TABLE departments (
  department_id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50) NOT NULL UNIQUE,
  location VARCHAR(50)
);
```

Oracle:

```sql
CREATE TABLE departments (
  department_id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR2(50) NOT NULL UNIQUE,
  location VARCHAR2(50)
)
```

Ghi chú: Oracle dùng `GENERATED BY DEFAULT AS IDENTITY` để Bài 5 còn tự điền mã được. Bản `GENERATED ALWAYS` không cho điền tay.

**Máy chấm kiểm**

- Tên table: `departments`.
- Tên column: `department_id`, `name`, `location`.
- Nhóm data type: `department_id` số nguyên. `name` và `location` chữ.
- Constraint: primary key trên `department_id`. Tự tăng trên `department_id`. NOT NULL trên `name`. UNIQUE trên `name`. `location` cho phép NULL.
- Phép thử hành vi:
  1. Thêm một phòng không có tên phải bị từ chối (MySQL 1048, Oracle ORA-01400).
  2. Thêm hai phòng cùng tên, phòng thứ hai phải bị từ chối (MySQL 1062, Oracle ORA-00001).
  3. Thêm hai phòng khác tên mà không ghi `department_id`, hai phòng phải nhận mã 1 và 2.

**Ba lỗi hay gặp**

1. Quên NOT NULL ở `name`. Phép thử 1 hỏng. Bi nói: "Mình thử thêm một phòng không có tên, và database nhận luôn. Phòng nào cũng phải có tên. Thêm luật gì sau `name VARCHAR(50)`?"
2. Viết `AUTO_INCREMENT` trong câu Oracle. Oracle báo lỗi cú pháp, mã ORA-00907 (cần kiểm tài liệu). Bi nói: "AUTO_INCREMENT là chữ của MySQL. Oracle tự tăng bằng cụm GENERATED BY DEFAULT AS IDENTITY."
3. Đặt UNIQUE cho `location` thay vì `name`. Phép thử 2 hỏng: hai phòng cùng tên vẫn vào được. Bi nói: "Mình thử hai phòng cùng tên và cả hai vào được. Column nào cần không trùng nhau?"

**Bốn bậc gợi ý**

1. Bậc 1 (nhắc hướng): "Nhìn lại bài 4 và bài 5. Mỗi yêu cầu trong danh sách là một luật gắn vào column."
2. Bậc 2 (nói cụ thể): "Cần primary key và mã tự tăng cho `department_id`. Cần NOT NULL và UNIQUE cho `name`. Column `location` không cần luật nào."
3. Bậc 3 (khung có chỗ trống):

```sql
CREATE TABLE departments (
  department_id INT ____ ____,
  name VARCHAR(50) ____ ____,
  location VARCHAR(50)
);
```

Khung Oracle:

```sql
CREATE TABLE departments (
  department_id NUMBER GENERATED BY DEFAULT AS IDENTITY ____,
  name VARCHAR2(50) ____ ____,
  location VARCHAR2(50)
)
```

4. Bậc 4 (gần như lời giải): hiện lời giải mẫu ở trên, che hai chữ `NOT NULL UNIQUE` của `name`.

## Bài 2: Table nhân viên

**Đề bài (Bi nói)**

"Chị Hạnh quay lại. Chị cần table nhân viên. Mỗi nhân viên có họ tên, email, ngày vào làm và lương. Họ tên, email, ngày vào làm và lương đều bắt buộc có. Email không trùng nhau, và lương phải lớn hơn 0. Nhân viên thuộc một phòng ban, và có một sếp. Sếp cũng là một nhân viên trong table này. Giám đốc thì không có sếp, nên chỗ sếp được để trống. Bạn dựng table này nhé."

**Yêu cầu**

- [ ] Table tên `employees`
- [ ] `employee_id`: số nguyên, primary key, tự tăng
- [ ] `full_name`: chữ tối đa 100 ký tự, bắt buộc có
- [ ] `email`: chữ tối đa 100 ký tự, bắt buộc có, không trùng nhau
- [ ] `hire_date`: ngày, bắt buộc có
- [ ] `salary`: số thập phân (12 chữ số, 2 chữ số sau dấu phẩy), bắt buộc có, lớn hơn 0
- [ ] `department_id`: số nguyên, foreign key trỏ sang `departments`, được để trống
- [ ] `manager_id`: số nguyên, foreign key trỏ về `employees`, được để trống

**Lời giải mẫu**

MySQL:

```sql
CREATE TABLE employees (
  employee_id INT AUTO_INCREMENT PRIMARY KEY,
  full_name VARCHAR(100) NOT NULL,
  email VARCHAR(100) NOT NULL UNIQUE,
  hire_date DATE NOT NULL,
  salary DECIMAL(12,2) NOT NULL CHECK (salary > 0),
  department_id INT,
  manager_id INT,
  FOREIGN KEY (department_id) REFERENCES departments (department_id),
  FOREIGN KEY (manager_id) REFERENCES employees (employee_id)
);
```

Oracle:

```sql
CREATE TABLE employees (
  employee_id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  full_name VARCHAR2(100) NOT NULL,
  email VARCHAR2(100) NOT NULL UNIQUE,
  hire_date DATE NOT NULL,
  salary NUMBER(12,2) NOT NULL CHECK (salary > 0),
  department_id NUMBER,
  manager_id NUMBER,
  FOREIGN KEY (department_id) REFERENCES departments (department_id),
  FOREIGN KEY (manager_id) REFERENCES employees (employee_id)
)
```

**Máy chấm kiểm**

- Tên table: `employees`.
- Tên column: `employee_id`, `full_name`, `email`, `hire_date`, `salary`, `department_id`, `manager_id`.
- Nhóm data type: `employee_id`, `department_id`, `manager_id` số nguyên. `full_name`, `email` chữ. `hire_date` ngày. `salary` số thập phân.
- Constraint: primary key và tự tăng trên `employee_id`. NOT NULL trên `full_name`, `email`, `hire_date`, `salary`. UNIQUE trên `email`. CHECK `salary > 0`. Foreign key `department_id` trỏ `departments(department_id)`. Foreign key `manager_id` trỏ `employees(employee_id)`. `department_id` và `manager_id` cho phép NULL.
- Phép thử hành vi:
  1. Thêm nhân viên lương âm phải bị từ chối (MySQL 3819, Oracle ORA-02290).
  2. Thêm nhân viên có `department_id` 99 (phòng không tồn tại) phải bị từ chối (MySQL 1452, Oracle ORA-02291).
  3. Thêm nhân viên đầu tiên với `manager_id` để trống phải được nhận. Rồi thêm nhân viên có `manager_id` 99 phải bị từ chối.

**Ba lỗi hay gặp**

1. Tạo `employees` trước khi có `departments`. MySQL báo 1824 (cần kiểm tài liệu), Oracle báo ORA-00942. Bi nói: "Table employees trỏ sang departments, mà departments chưa có. Table được trỏ tới phải có trước. Bạn đã làm table nào ở bài 1?"
2. Viết `manager_id INT NOT NULL`. Phép thử 3 hỏng: giám đốc không có sếp nên không thêm được nhân viên đầu tiên. Bi nói: "Mình thử thêm giám đốc, người không có sếp, và database từ chối. Column manager_id có nên bắt buộc không?"
3. Cho `manager_id` data type khác `employee_id`, ví dụ `VARCHAR(10)`. Database báo hai column không tương thích: MySQL 3780, Oracle ORA-02267 (cần kiểm tài liệu cả hai). Bi nói: "Foreign key và column nó trỏ tới phải cùng nhóm data type. employee_id là số nguyên, nên manager_id cũng phải là số nguyên."

**Bốn bậc gợi ý**

1. Bậc 1: "Sếp cũng là nhân viên. Vậy table employees trỏ về chính nó. Column nào đảm nhận phần đó?"
2. Bậc 2: "`department_id` trỏ sang departments. `manager_id` trỏ sang `employee_id` của chính table employees. Cả hai được để trống. Lương cần CHECK lớn hơn 0."
3. Bậc 3 (khung):

```sql
CREATE TABLE employees (
  employee_id INT AUTO_INCREMENT PRIMARY KEY,
  full_name VARCHAR(100) ____,
  email VARCHAR(100) ____ ____,
  hire_date ____ NOT NULL,
  salary ____ NOT NULL CHECK (____),
  department_id INT,
  manager_id INT,
  FOREIGN KEY (department_id) REFERENCES ____ (____),
  FOREIGN KEY (manager_id) REFERENCES ____ (____)
);
```

Khung Oracle thay `INT AUTO_INCREMENT PRIMARY KEY` bằng `NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`, `INT` bằng `NUMBER`, `VARCHAR` bằng `VARCHAR2`.

4. Bậc 4: hiện lời giải mẫu, che hai khai báo FOREIGN KEY cuối.

## Bài 3: Dự án và phân công

**Đề bài (Bi nói)**

"Anh Quân, trưởng phòng kỹ thuật, muốn theo dõi các dự án. Mỗi dự án có tên, ngày bắt đầu, ngày kết thúc và ngân sách. Dự án đang chạy thì chưa có ngày kết thúc. Ngày kết thúc không được trước ngày bắt đầu. Anh cũng cần biết ai làm dự án nào. Một nhân viên làm nhiều dự án. Một dự án có nhiều nhân viên. Mỗi cặp nhân viên và dự án chỉ ghi một lần, kèm vai trò và số giờ mỗi tuần. Bạn dựng hai table giúp anh nhé."

**Yêu cầu**

- [ ] Table `projects`: `project_id` (số nguyên, primary key, tự tăng), `name` (chữ tối đa 100, bắt buộc), `start_date` (ngày, bắt buộc), `end_date` (ngày, được để trống), `budget` (số thập phân 12 chữ số, 2 chữ số sau dấu phẩy, không âm)
- [ ] Ngày kết thúc không được trước ngày bắt đầu
- [ ] Table `assignments`: `employee_id` (số nguyên), `project_id` (số nguyên), `role_name` (chữ tối đa 50, bắt buộc), `hours_per_week` (số nguyên, mặc định 10, từ 1 tới 40)
- [ ] Primary key của `assignments` ghép từ `employee_id` và `project_id`
- [ ] `employee_id` trỏ sang `employees`, `project_id` trỏ sang `projects`

**Lời giải mẫu**

MySQL:

```sql
CREATE TABLE projects (
  project_id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  start_date DATE NOT NULL,
  end_date DATE,
  budget DECIMAL(12,2) CHECK (budget >= 0),
  CHECK (end_date IS NULL OR end_date >= start_date)
);

CREATE TABLE assignments (
  employee_id INT NOT NULL,
  project_id INT NOT NULL,
  role_name VARCHAR(50) NOT NULL,
  hours_per_week INT DEFAULT 10 CHECK (hours_per_week BETWEEN 1 AND 40),
  PRIMARY KEY (employee_id, project_id),
  FOREIGN KEY (employee_id) REFERENCES employees (employee_id),
  FOREIGN KEY (project_id) REFERENCES projects (project_id)
);
```

Oracle:

```sql
CREATE TABLE projects (
  project_id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR2(100) NOT NULL,
  start_date DATE NOT NULL,
  end_date DATE,
  budget NUMBER(12,2) CHECK (budget >= 0),
  CHECK (end_date IS NULL OR end_date >= start_date)
);

CREATE TABLE assignments (
  employee_id NUMBER NOT NULL,
  project_id NUMBER NOT NULL,
  role_name VARCHAR2(50) NOT NULL,
  hours_per_week NUMBER DEFAULT 10 CHECK (hours_per_week BETWEEN 1 AND 40),
  PRIMARY KEY (employee_id, project_id),
  FOREIGN KEY (employee_id) REFERENCES employees (employee_id),
  FOREIGN KEY (project_id) REFERENCES projects (project_id)
)
```

(Trong tool của khóa học, mỗi câu chạy riêng. Người học gõ hai câu, và cảnh chạy lần lượt từng câu.)

**Máy chấm kiểm**

- Tên table: `projects` và `assignments`.
- Tên column: đủ theo yêu cầu.
- Nhóm data type: `project_id`, `employee_id`, `hours_per_week` số nguyên. `name`, `role_name` chữ. `start_date`, `end_date` ngày. `budget` số thập phân.
- Constraint: primary key và tự tăng trên `projects.project_id`. NOT NULL trên `projects.name`, `projects.start_date`, `assignments.role_name`. `end_date` cho phép NULL. CHECK ngân sách không âm. CHECK ngày kết thúc. CHECK `hours_per_week` từ 1 tới 40. DEFAULT 10 trên `hours_per_week`. Primary key ghép hai column của `assignments`. Hai foreign key của `assignments`.
- Phép thử hành vi:
  1. Thêm dự án có `end_date` trước `start_date` phải bị từ chối (MySQL 3819, Oracle ORA-02290). Thêm dự án có `end_date` để trống phải được nhận.
  2. Thêm cùng một cặp nhân viên và dự án hai lần, lần hai phải bị từ chối (MySQL 1062, Oracle ORA-00001).
  3. Phân công nhân viên 99 (không tồn tại) phải bị từ chối (MySQL 1452, Oracle ORA-02291). Thêm một phân công không ghi `hours_per_week` thì `hours_per_week` phải là 10 (engine sẽ thêm).

**Ba lỗi hay gặp**

1. Viết `employee_id INT PRIMARY KEY, project_id INT PRIMARY KEY`, mỗi column một primary key riêng. MySQL báo 1068, Oracle báo ORA-02260 (cần kiểm tài liệu cả hai). Bi nói: "Một table chỉ có một primary key. Khi cặp hai column mới là mã riêng, ta khai cả hai trong một cặp ngoặc riêng: PRIMARY KEY (a, b)."
2. Quên khai primary key ghép. Phép thử 2 hỏng: nhân viên được ghi hai lần vào cùng dự án. Bi nói: "Mình thử ghi một người vào cùng dự án hai lần và database nhận cả hai. Mỗi cặp chỉ được một lần. Luật nào giữ chuyện đó?"
3. Viết `end_date DATE NOT NULL`. Phép thử 1 hỏng: dự án chưa kết thúc không thêm được. Bi nói: "Dự án đang chạy chưa có ngày kết thúc. Column end_date có nên bắt buộc không?"

**Bốn bậc gợi ý**

1. Bậc 1: "Table assignments nối hai table. Mỗi row là một cặp nhân viên và dự án. Cặp đó cần một mã duy nhất."
2. Bậc 2: "Primary key của assignments gồm hai column cùng nhau. Mỗi column riêng cũng là foreign key. CHECK ngày kết thúc cần cho phép `end_date` là NULL."
3. Bậc 3 (khung cho `assignments`):

```sql
CREATE TABLE assignments (
  employee_id INT NOT NULL,
  project_id INT NOT NULL,
  role_name VARCHAR(50) NOT NULL,
  hours_per_week INT ____ 10 CHECK (hours_per_week ____ 1 AND 40),
  PRIMARY KEY (____, ____),
  FOREIGN KEY (employee_id) REFERENCES ____ (____),
  FOREIGN KEY (project_id) REFERENCES ____ (____)
);
```

Khung Oracle đổi `INT` thành `NUMBER`, `VARCHAR` thành `VARCHAR2`.

4. Bậc 4: hiện lời giải mẫu, che câu CHECK về ngày của `projects`.

## Bài 4: Đơn xin nghỉ phép

**Đề bài (Bi nói)**

"Chị Hạnh cần table đơn xin nghỉ phép. Mỗi đơn ghi nhân viên nào xin, nghỉ từ ngày nào tới ngày nào và lý do. Ngày kết thúc không được trước ngày bắt đầu. Đơn mới tạo có trạng thái chờ duyệt. Trạng thái chỉ là một trong ba giá trị: chờ duyệt, đã duyệt, từ chối. Người duyệt cũng là một nhân viên, nhưng đơn mới chưa có ai duyệt. Bạn dựng table giúp chị nhé."

**Yêu cầu**

- [ ] Table tên `leave_requests`
- [ ] `request_id`: số nguyên, primary key, tự tăng
- [ ] `employee_id`: số nguyên, bắt buộc có, trỏ sang `employees`
- [ ] `start_date` và `end_date`: ngày, bắt buộc có, ngày kết thúc không trước ngày bắt đầu
- [ ] `reason`: chữ tối đa 200 ký tự, được để trống
- [ ] `status`: chữ tối đa 20 ký tự, mặc định `'pending'`, chỉ nhận `'pending'`, `'approved'`, `'rejected'`
- [ ] `approved_by`: số nguyên, trỏ sang `employees`, được để trống

**Lời giải mẫu**

MySQL:

```sql
CREATE TABLE leave_requests (
  request_id INT AUTO_INCREMENT PRIMARY KEY,
  employee_id INT NOT NULL,
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  reason VARCHAR(200),
  status VARCHAR(20) DEFAULT 'pending' NOT NULL,
  approved_by INT,
  CHECK (end_date >= start_date),
  CHECK (status IN ('pending', 'approved', 'rejected')),
  FOREIGN KEY (employee_id) REFERENCES employees (employee_id),
  FOREIGN KEY (approved_by) REFERENCES employees (employee_id)
);
```

Oracle:

```sql
CREATE TABLE leave_requests (
  request_id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  employee_id NUMBER NOT NULL,
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  reason VARCHAR2(200),
  status VARCHAR2(20) DEFAULT 'pending' NOT NULL,
  approved_by NUMBER,
  CHECK (end_date >= start_date),
  CHECK (status IN ('pending', 'approved', 'rejected')),
  FOREIGN KEY (employee_id) REFERENCES employees (employee_id),
  FOREIGN KEY (approved_by) REFERENCES employees (employee_id)
)
```

Ghi chú: ở Oracle, DEFAULT phải đứng trước NOT NULL. Bản MySQL viết cùng thứ tự cho dễ nhớ.

**Máy chấm kiểm**

- Tên table: `leave_requests`.
- Tên column: `request_id`, `employee_id`, `start_date`, `end_date`, `reason`, `status`, `approved_by`.
- Nhóm data type: `request_id`, `employee_id`, `approved_by` số nguyên. `reason`, `status` chữ. `start_date`, `end_date` ngày.
- Constraint: primary key và tự tăng trên `request_id`. NOT NULL trên `employee_id`, `start_date`, `end_date`, `status`. DEFAULT `'pending'` trên `status`. CHECK ngày. CHECK trạng thái. Hai foreign key. `reason` và `approved_by` cho phép NULL.
- Phép thử hành vi:
  1. Thêm đơn có `end_date` trước `start_date` phải bị từ chối (MySQL 3819, Oracle ORA-02290).
  2. Thêm đơn có `status` là `'maybe'` phải bị từ chối (MySQL 3819, Oracle ORA-02290).
  3. Thêm đơn không ghi `status` và không ghi `approved_by` phải được nhận, và `status` phải là `'pending'` (engine sẽ thêm).

**Ba lỗi hay gặp**

1. Oracle: viết `NOT NULL DEFAULT 'pending'` theo thứ tự ngược. Oracle báo lỗi cú pháp, mã ORA-00907 (cần kiểm tài liệu). Bi nói: "Oracle đọc DEFAULT trước, rồi mới tới NOT NULL. Đổi chỗ hai cụm này."
2. Viết giá trị trong CHECK bằng dấu ngoặc kép `"pending"`. MySQL vẫn nhận, nhưng Oracle coi đó là tên column và báo ORA-00904 (cần kiểm tài liệu). Bi nói: "Chữ trong SQL nằm giữa hai dấu nháy đơn. Dấu ngoặc kép dành cho tên."
3. Viết `approved_by INT NOT NULL`. Phép thử 3 hỏng: đơn mới chưa có ai duyệt nên không thêm được. Bi nói: "Mình thử thêm đơn mới và database từ chối vì thiếu người duyệt. Đơn mới chưa có ai duyệt. Column này có nên bắt buộc không?"

**Bốn bậc gợi ý**

1. Bậc 1: "Có ba luật kiểu CHECK trong đề: ngày, trạng thái, và mặc định. Hãy gạch dưới từng luật trong đề bài."
2. Bậc 2: "Table cần hai CHECK riêng: một cho ngày, một cho `status IN (...)`. Column `status` cần DEFAULT. `approved_by` được để trống."
3. Bậc 3 (khung):

```sql
CREATE TABLE leave_requests (
  request_id INT AUTO_INCREMENT PRIMARY KEY,
  employee_id INT NOT NULL,
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  reason VARCHAR(200),
  status VARCHAR(20) ____ 'pending' NOT NULL,
  approved_by INT,
  CHECK (end_date ____ start_date),
  CHECK (status ____ ('pending', ____, ____)),
  FOREIGN KEY (employee_id) REFERENCES ____ (____),
  FOREIGN KEY (approved_by) REFERENCES ____ (____)
);
```

Khung Oracle đổi `INT` thành `NUMBER`, `VARCHAR` thành `VARCHAR2`.

4. Bậc 4: hiện lời giải mẫu, che cả hai câu CHECK.

## Bài 5: Nạp dữ liệu đúng thứ tự

**Đề bài (Bi nói)**

"Năm table đã dựng xong, nhưng còn rỗng. Chị Hạnh gửi mình danh sách thật để nạp vào: hai phòng ban, bốn nhân viên, hai dự án, ba lượt phân công và hai đơn nghỉ phép. Table con chỉ nhận row khi table cha đã có row tương ứng. Bạn tìm thứ tự đúng để nạp. Sếp phải vào trước người dưới quyền."

**Yêu cầu**

- [ ] Hai phòng ban: `Kinh doanh` ở Hà Nội, `Kỹ thuật` ở TP. Hồ Chí Minh
- [ ] Bốn nhân viên: Trần Văn An (không có sếp, phòng 1), Lê Thị Bình (sếp là An, phòng 1), Phạm Quốc Cường (sếp là An, phòng 2), Đỗ Thu Dung (sếp là Cường, phòng 2)
- [ ] Hai dự án: `Mở tiệm mới` (có ngày kết thúc) và `App đặt trà` (chưa có ngày kết thúc)
- [ ] Ba lượt phân công: Bình vào dự án 1, Cường và Dung vào dự án 2
- [ ] Hai đơn nghỉ phép: một đơn đã duyệt (An duyệt), một đơn mới, chưa ghi trạng thái
- [ ] Thứ tự nạp: phòng ban, nhân viên, dự án, phân công, đơn nghỉ phép
